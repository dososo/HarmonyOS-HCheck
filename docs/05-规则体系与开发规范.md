# 规则体系与开发规范

## Finding 三轴

每个 Finding 独立表达：

| 维度 | 作用 |
|---|---|
| 严重性 | `BLOCKER`、`HIGH`、`MEDIUM`、`LOW`、`INFO`，决定风险优先级 |
| 置信度 | `CONFIRMED`、`PROBABLE`、`POSSIBLE`、`MANUAL`，描述证据强度 |
| 适用性 | `APPLICABLE`、`NOT_APPLICABLE`、`UNKNOWN`，描述是否适用于当前工程 |

规则命中不等于应用必然无法通过审核；反之，零 Finding 也不等于所有审核要求都被覆盖。

## 新增或修改规则

1. 使用 [规则模板](../templates/rule-template.yml) 定义 ID、范围、证据、默认严重性、置信度、来源和复验方法。
2. 为规则加入至少一个应命中、一个不应命中和一个边界/不确定样例。
3. 断言规则 ID、严重性、置信度、适用性、脱敏输出与稳定指纹。
4. 明确规则无法覆盖的 API、版本或运行时条件，不能扩大结论。
5. 在变更说明中标注官方资料与核验日期；外部事实需要在合并前重新核验。

规则和示例必须可由 `pnpm schema:check` 校验。规则不得执行任意脚本、上传源码或依赖未记录的私有接口。
