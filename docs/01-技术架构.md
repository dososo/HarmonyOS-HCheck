# 技术架构

## 目标

HCheck 将项目输入、规则与报告解耦：同样的输入、配置和规则包应得到稳定、可解释的结果；外部环境不可用时应明确报告证据不完整。

```text
CLI
  ↓
项目与软件包读取 → 规则引擎 → Finding 三轴模型 → 报告器
  ↓                    ↓                 ↓             ↓
受限文件系统          适用性判断          脱敏           Terminal / JSON / SARIF / JUnit / HTML
  ↓
外部能力端口（Hvigor / HDC / AGC / AppAnalyzer / DevEco Testing）
```

## 包边界

| 位置 | 职责 |
|---|---|
| `packages/core` | 领域类型、错误、Finding、运行时流程与稳定排序 |
| `packages/config` | 配置 Schema、加载与安全默认值 |
| `packages/project-model` | 工程发现、JSON5、依赖与软件包受限读取 |
| `packages/rule-engine` | 规则加载、适用性、检测器、基线与抑制 |
| `packages/reporters` | 终端与机器可读报告、统一脱敏 |
| `packages/cli` | 参数解析、命令组装与退出码 |
| `adapters/*` | 外部工具与服务的可注入适配器 |

核心领域不直接依赖 DevEco Studio 路径、真实 HDC 进程、AGC HTTP 客户端或全局文件系统。外部交互必须通过明确端口注入，以便单元测试使用录制或内存实现。

## 可靠性与安全边界

- 进程调用使用可执行文件与参数数组，不使用 shell 拼接；
- 本地路径、密钥模式和敏感字段在报告输出前脱敏；
- 解析器限制路径穿越、符号链接、压缩包炸弹、损坏包与超大输入；
- 工具失败、超时、缺失和证据不完整是独立状态，不能映射为 PASS；
- 自动修复只生成受限的 dry-run 计划，不隐式改写用户代码。
